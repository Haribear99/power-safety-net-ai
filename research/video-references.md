# 3분 이하 시연영상 레퍼런스 분석 (3편)

작성 2026-10-31. 목적: KEIT 2026 AI 라이프 솔루션 챌린지 제출용 3분 시연영상(웹 화면 녹화 + TTS 내레이션 + 자막)의 구조 설계 근거.

## 0. 분석 방법과 한계

- 영상: `yt-dlp`로 360p **영상 트랙만** 받음(JS 런타임 부재로 결합 포맷 불가). 소리는 직접 듣지 않았고, 내레이션은 YouTube 자막(VTT)으로 확인.
  - Vite Vere는 이탈리아어 내레이션. 영상에 영어 자막이 박혀 있고, 분석은 그 영어 자막·자동 번역 자막 기준.
  - Jayu·ATTI는 영어 자동 생성 자막(오인식 있음, 예: "Jayu"→"Jau").
- 화면: 2.5초 간격 썸네일 시트(16컷 단위) + 첫·마지막 10초는 1초 간격으로 직접 보고 판단. 장면 전환은 ffmpeg `select='gt(scene,0.3)'`로 셈(디졸브·슬라이드 같은 부드러운 전환은 잡히지 않아 실제 컷 수보다 적게 나올 수 있음).
- 시각(초)은 ±1~2.5초 오차.
- 조회수는 2026-10-31 yt-dlp로 읽은 값.
- 내레이션 목소리가 사람인지 TTS인지는 **미확인**(영상만 받았기 때문).

## 3. 공통 구조와 차이

**공통**
1. **첫 10초에 제품 기능을 보여 주지 않는다.** 사람(A), 정체성과 비유(B), 사회 문제(C) 중 하나로 연다.
2. **해법을 한 문장으로 말하는 지점이 따로 있다.** A 62초, B 4–12초, C 20–32초.
3. **시연이 가장 길다**(35~80%). 시연은 "사용자 행동 → 시스템 반응"을 한 쌍씩 끊어 보여 준다.
4. **사용자 입력이나 시스템 출력을 화면에 글자로 고정한다.** A는 앱 음성을 따옴표 자막으로, B는 "Prompt:" 바로, C는 큰 말풍선과 콜아웃으로.
5. **기술 스택은 5~20초 로고로만 보여 준다.** 아키텍처 설명은 없다.
6. **마지막 5~10초는 로고와 한 줄 메시지.** 정량 성과(사용자 수·실증 결과)를 제시한 영상은 없다. C만 문제 통계를 쓴다.

**차이**

| 축 | A Vite Vere(대중 투표상) | B Jayu(최고상) | C ATTI(Top 3) |
|---|---|---|---|
| 감정선 | 실제 사용자 주인공과 수미상관. 가장 강함 | 유머·자신감 | 담백, 정보 전달 |
| 시연 방식 | 앱 화면 + 실제 사용 실사 **분할 화면** | 실제 PC 화면 롱테이크 + 로그 | 폰 목업 + 고정 템플릿 + 콜아웃 |
| 근거 | 실제 사용자 장면 | 실제 동작 로그 | 언론 헤드라인 + 공공 통계 |
| 한계 고지 | 엔드 카드에 명시 | 설명란에만 | 없음 |
| 자막 | 노란 박스 번인, 상시 | 명령 바만 | 하단 흰 띠, 상시 |

**대국민 투표 관점 해석**
- 대중 투표상(A)은 **"누가, 왜 필요한지"를 사람 얼굴로 보여 준** 영상이었다. 기술 설명은 15% 남짓이다.
- 전문가 대상(B)은 "진짜 돌아간다"는 증거(로그·롱테이크)가 강점이었다.
- 우리는 두 심사를 모두 받으므로 다음처럼 섞는 것이 맞다.
  - 앞 30초: A·C식(사람·문제·근거)
  - 시연: C식 템플릿 + B식 실제 동작 증거
  - 끝: A식 한계 고지 + 수미상관

## 4. 우리 영상에 적용할 항목 (12개)

전제: 총 180초, 웹 화면 녹화 + TTS + 번인 자막. 아래 초 단위는 권장안이다. 수치·뉴스는 **검증된 실제 자료만** 쓰고 출처를 화면 하단에 표기한다(지어내지 말 것).

1. **0–3초 질문형 한 문장 훅**(C의 0초 + B의 즉시성): 어두운 배경에 큰 글씨 한 줄, 예: "정전, 인공호흡기 배터리는 몇 시간 남았을까?" 핵심어("배터리", "몇 시간")만 강조색. 3초 안에 주제가 들리게 TTS 첫 문장도 같은 내용으로.
2. **3–6초 실제 언론 헤드라인 2~3개 캡처**(C 2–4초): 정전 시 재택 의료기기 사용자 피해·우려 기사. 매체명과 날짜를 붙인다. 실제 기사가 확보되지 않으면 이 컷을 빼고 2번 항목은 통계로만 간다.
3. **6–12초 통계 한 장, 숫자 하나만 강조**(C 8–14초): 재택 인공호흡기·산소발생기 사용 가구 규모 등 이미 검증한 수치 1~2개만 크게 + 출처 한 줄. 숫자가 3개를 넘으면 투표자가 기억하지 못한다.
4. **12–25초 가상 사례 인물 카드 + 하단자막 태그**(A 0–2초): 예: "○○동 · 70대 · 재택 산소발생기 사용"(화면에 **"가상 사례"** 명시). 실사 대신 일러스트나 앱 내 가구 카드로 대신하되, A처럼 이름·나이·상황 태그를 고정해 "한 사람의 이야기"로 만든다.
5. **25–35초 해법 한 문장 + 비유**(B 4–12초): "정전 순간, 가구마다 남은 배터리 시간을 계산해 담당자가 비상전원을 먼저 보낼 집을 승인하는 서비스" 한 문장. 쉬운 비유 하나를 덧붙인다(예: "정전 때의 배터리 계기판"). 제품명은 이 구간에서 처음 크게 띄운다.
6. **35–40초 문제→기능 대응표 한 장**(C 20–32초 타임라인): 왼쪽 "어려움"(배터리 남은 시간 모름 / 누구부터 지원할지 모름 / 승인 기록 없음), 오른쪽 기능(시간 계산 / 우선순위 / 담당자 승인)이 하나씩 붙는 애니메이션.
7. **40–150초 시연 고정 템플릿**(C 40–113초): 웹은 가로 화면이므로 상단 얇은 띠에 `[가구 화면]` / `[담당자 화면]` 태그 + 기능 제목 한 줄. 아래에 화면 녹화를 꽉 채우고, 맨 아래에 자막 띠. **역할이 바뀌는 순간 태그 색을 바꾼다**(C 103초에서 `a patient's carer`로 바뀐 방식).
8. **설명하는 UI 요소마다 콜아웃 + 확대**(C 콜아웃): TTS가 "남은 시간"을 말하는 순간 해당 숫자에 강조색 외곽선 + 1.5배 줌. 대상은 배터리 남은 시간, 위험 단계, 승인 버튼, 배정 결과 4곳이면 충분하다.
9. **사람이 한 행동은 하단 '행동 바'로 글자 고정**(B "Prompt:" 바): 예: "담당자: ○○동 가구 비상전원 배정 승인". 클릭 한 번이 무엇을 뜻하는지 투표자가 읽을 수 있게 한다. 시스템 출력은 따옴표로 구분한다(A의 앱 음성 인용 방식). 예: 시스템 "예상 잔여 2시간 10분".
10. **승인 → 결과 반영은 분할 화면으로 동시에**(A 62–140초 분할): 왼쪽 담당자 화면에서 승인을 누르면 오른쪽 가구 화면 상태가 바뀌는 장면을 한 컷에 보여 준다. 실제 동작 증거(B의 로그)로서 화면 전환 없이 롱테이크 5~8초를 유지하고 편집으로 숫자를 바꾸지 않는다.
11. **150–160초 부가 기능 몽타주 + 기술 로고 5초 이내**(B 147–157초, A 78–96초): 기록 조회·알림 등 부가 기능을 1~1.5초 컷 4~5개로 압축한다. AI·데이터 출처 로고나 한 줄 설명은 5초 이내로. 전문가 심사용으로 "계산 근거"는 한 줄("기기 소비전력 × 배터리 용량 기준 추정")만 넣는다.
12. **160–180초 한계 고지 → 수미상관 → 엔드 카드**(A 171–180초):
    - 160–167초: "의료 판단을 대체하지 않으며 최종 배정은 담당자가 승인" 같은 한계·안전장치 한 줄(A의 고지문). 우리 작품의 사람 승인 구조를 신뢰 근거로 바꾸는 지점이다.
    - 167–174초: 4번의 인물 카드로 돌아가 "비상전원 도착" 상태를 보여 준다.
    - 174–180초: 로고 + 한 줄 태그라인(C처럼 태그라인 속 핵심어 하나를 강조색으로) + 팀명·서비스 주소.
    - 투표 독려 문구(A 설명란 방식)는 **공모전 규정 허용 여부를 확인한 뒤에만** 넣는다(현재 미확인).

**전 구간 공통 규칙**
- 번인 자막 상시, 구 단위로 2~3초씩 끊고 최대 2줄. 고대비 박스형(A의 노란 박스+검정 글씨처럼 배경과 무관하게 읽히게).
- 핵심어 강조색은 한 가지만(C의 주황 1색).
- 컷 길이:
  - 문제 파트는 2~4초(A 평균 5.3초보다 짧게)
  - 시연 파트는 동작 하나가 끝날 때까지 롱테이크(B)
