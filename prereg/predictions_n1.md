# N1 사전등록: 보호자 알림(쉬운 글·음성)의 AI 문장과 두 단계 검사 (2026-10-18)

## 왜 N1인가

- **원안 기능이다.** 원안 제안서에 "이용자에게는 쉬운 글·음성·보호자 알림으로 완충, 대체장소, 119·123 연락 … 안내한다"는 문구가 있다. 지금까지 출품작에는 생성형 AI 기능이 없었다(레드팀 득점 위험 R1).
- **AI가 직접 문장을 쓴다.** 생명과 이어진 안내문이므로, 사실이 틀린 글이 나가지 않는 구조인지를 잰다.
- **레드팀이 첫 설계를 깼다(10/18 봉인 전).** 첫 설계는 글자 규칙 검증기 하나였는데, 다음 결함이 나왔다.
  - '119에 전화하지 마세요', '기기를 꺼 주세요', '내일'을 붙여 날짜를 하루 미루기, '이후'로 뜻 뒤집기가 모두 검사를 통과했다.
  - 산소통 시간을 배터리 시간으로 안내했다.
  - 자기 확인식 지표(변이 시험 100%)를 썼다.
  - 시험셋이 dev와 겹쳤다.
- **그래서 다시 설계했다.**
  - 사실과 할 일은 코드가 정한다. 119·123 문장도 코드가 붙인다.
  - AI(Claude Sonnet)는 본문만 쓴다.
  - 1차 검사는 글자 규칙이다.
  - 2차 검사는 다른 모델(Claude Opus)이 사실표 없이 글만 읽고 주장을 뽑게 한 뒤, 코드가 그 주장을 사실과 대조한다.
  - 둘 다 통과할 때만 발송하고, 아니면 고정 문안을 보낸다. 검사가 실패해도 고정 문안을 보낸다(실패 시 닫힘).

## 0. 설계

- **시험셋**
  - 60건, 24개 시나리오(LHS 마스터 `N1`)로 만들고 층별 라운드로빈으로 고른다. dev와 같은 사실 묶음은 뺀다.
  - 시나리오 시드는 S9 태그 커밋 시각 T에 900초를 더한 시각 이후의 첫 drand quicknet 라운드 R의 난수로 정한다. R = ceil((T + 900 − 1692803367)/3) + 1.
  - seedLo = 7,000,000 + (난수 앞 8자리 16진수 mod 900,000)이다.
  - 그러므로 봉인 전에는 시험셋을 만들 수 없다.
  - 생성 경로는 /ops 화면과 같다: 세션 시작 → RULE 추천 → 알림 입력이다. 2시간 뒤 시점과 수동검토의 '수정' 입력도 포함한다.
- **독립 우회 모음**
  - 파일은 `datasets/notice/adversarial_test.json`, sha256 `c956fdcb…5ba14`이다.
  - 100건(bad 70, good 30)이다. 개발자가 아닌 독립 레드팀 에이전트가 코드를 보고(화이트박스) 썼다.
  - 개발자는 개수, 범주, 1차 검사 통과 수, 해시만 받았고 내용은 보지 않았다.
  - 작성자 보고: bad 70건 중 54건이 1차 검사를 통과한다(뜻만 틀린 글). good 30건 중 27건이 1차 검사를 통과한다.
  - 라벨은 작성자의 판단이다.
- **실행**
  - `npx tsx scripts/n1-run.ts --sealed`로 시험셋과 우회 모음을 한 번에, 1회만 돌린다. 시작 표지 파일이 있으면 다시 실행하지 않는다.
  - 생성은 프롬프트 n1-v7, 검사는 n1-check-v6, 심사는 n1-judge-v3이다.
- **지표**
  - 시험셋 AI 발송률: 두 검사를 모두 통과한 비율.
  - 정답 글(고정 문안) 2차 검사 오거부율.
  - 우회 모음 bad 놓침률: 두 검사를 모두 통과한 비율.
  - 우회 모음 good 오거부율.
  - 탐색 지표: Opus 눈가림 쌍 비교(AI 글 대 같은 내용의 고정 문안).
  - 끝에서 끝까지의 지연.
  - 비율에는 Wilson 95% CI를 붙인다.
- **코드**
  - `app/src/lib/notice/*`, `app/scripts/n1-build-set.ts`, `app/scripts/n1-run.ts`, `tools/notice_check.py`.
  - sha256은 `prereg/n1.json`에 있다.

## 2. 사용 규칙(결과 보기 전 고정)

- 보고서와 랜딩에는 9.1(놓침), 9.2(오거부), 9.3(발송률)을 Wilson 95% CI와 함께 싣는다. 우회 모음은 '독립 레드팀이 쓴 100건'으로 적는다.
- '사실 오류 0 보장', '안전한 안내' 같은 말은 쓰지 않는다. 검사가 보는 범위(시각·수단·경고·할 일·금지 표현)를 적는다.
- 9.6은 'AI가 판정한 탐색 지표' 표지 없이 싣지 않는다. 사람 평가는 하지 않았다.
- 9.1이 틀리면 놓친 글의 수와 범주를 그대로 쓰고, 기능은 '시연용·담당자 확인 뒤 발송'으로만 적는다.
- 봉인 뒤 코드를 고치면 `seal/CHANGELOG.md`에 적고, 봉인 측정은 봉인 당시 코드의 결과로만 인용한다.
