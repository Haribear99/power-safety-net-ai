# E6 사전등록: 평시 정보만 쓰는 표적 사전 배치 (2026-10-18)

## 왜 E6인가

레드팀 3라운드(10/18)는 E5의 표적 배치(P7T)에 두 가지 문제가 있다고 지적했다.

- **정전 시점 정보를 미리 썼다.** P7T는 순위 키로 정전 중 신고 시각과 그때의 충전량을 반영한 하한 끝을 썼다. 정전 전에는 알 수 없는 정보다. 그래서 E5의 1시간급 56.3%는 낙관 상한이다.
- **사전등록 사용 규칙을 지키지 않았다.** 보고서에 등록 지표 6.6 대신 하위군(6.7) 값을 실었다.

E6는 정전 전 등록부에 있을 정보만으로 순위를 매긴 P7P를 같은 시나리오에서 P7·P7T와 비교한다.

## 0. 설계

- **정전·갈래·시드 규칙**
  - E5와 같은 실측 분포 `APT_EMP`를 쓴다. 갈래는 AI(미확인 24/90)이고 정책은 RULE이다.
  - LHS 마스터는 `E6`이다.
  - 봉인 실행: 시드 6,000,001~6,002,000, 2,000추첨, 1회만 돌린다.
  - 예비 실행: 시드 9,801~10,000(마스터 `E6-dev`)으로 버그 확인만 한다. 예비 실행을 본 뒤 예측을 더하지 않는다.
- **변형:** `AI@RULE`, `AI@RULE+P7`(무작위), `AI@RULE+P7P`(평시 정보 표적), `AI@RULE+P7T`(E5와 같은 정전 시점 정보 표적, 낙관 상한)
- **P7P 순위 키:** 평시 하한 시간이다.
  - 쓰는 정보는 기종 사양(평시 수동검토로 확인된 기종), 배터리 연식(모르면 보수 계수), 외장 배터리 신고다.
  - 충전량은 모름으로 두고, 신고 시각은 0으로 둔다.
  - 이 하한이 짧은 등록 가구부터 P7과 같은 양 round(0.6 × covMult × N)을 준다. 고장·에너지·효율은 P7과 같다.
- **지표**
  - 공백 가구·시간 감소율 = 1 − ΣM2(변형)/ΣM2(기준)이다. 95% CI는 부트스트랩 2,000회로 구하고, 추첨 오차만 반영한다.
  - 등급별 공백 가구 비율도 계산한다.
- **코드:** `app/src/lib/sim/e6.ts`, `app/scripts/sweep.ts`(E6 분기), `app/scripts/e6-analyze.ts`(채점). sha256은 `prereg/e6.json`에 있다.

## 1. 예측 (E6 실행 전, E6 출력 0줄인 상태에서 커밋)

| # | 예측 | 판정 규칙 |
|---|---|---|
| 7.1 | 평시 정보만으로 골라도 무작위보다 공백을 더 줄인다 | P7P 대 P7 감소율 95% CI 하한 > 0 |
| 7.2 | 평시 정보 표적은 정전 시점 정보 표적보다 덜 준다 | P7P 대 P7 감소율 점추정 < P7T 대 P7 감소율 점추정 |
| 7.3 | 1시간급 인공호흡기 공백 가구 비율이 무작위보다 낮다 | VENT_1H 비율 P7P < P7 |
| 7.4 | 배터리 없는 산소발생기 공백 가구 비율이 무작위보다 낮다 | O2_STAT 비율 P7P < P7 |
| 7.5 | 3시간급과의 맞바꿈이 평시 정보에서도 남는다 | VENT_3H 비율 P7P > P7 |

## 2. 사용 규칙(결과 보기 전 고정)

- 보고서·랜딩에는 다음 세 가지만 싣는다.
  - 7.1의 감소율(P7P 대 P7)
  - P7 → P7P의 VENT_1H 비율
  - 공백 비율이 나빠진 등급 목록
- P7T(정전 시점 정보) 값은 '낙관 상한'이라는 표지 없이 싣지 않는다.
- 7.1이 틀리면(CI 하한 ≤ 0) 「평시 정보만으로는 표적 배치의 이득이 확인되지 않음」으로 쓴다.
