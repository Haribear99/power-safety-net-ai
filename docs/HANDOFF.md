## 1. 3분 요약

**무엇을 만들었나.** 정전이 나면 인공호흡기·산소발생기를 쓰는 집마다 *배터리가 먼저 끝날지, 전기(또는 비상전원)가 먼저 올지*를 계산합니다. 그 결과로 담당자에게 처리 순서와 맞는 비상전원을 제안하는 운영자 도구입니다. 배정은 담당자가 승인해야만 이뤄지고, 119에는 위치·기기·예상 안전시간 세 가지만 넘어갑니다.

**왜 필요한가.** 공개된 정전 복구·순환단전 절차에는 "어느 집이 먼저 꺼지는지" 계산하는 단계가 없습니다. 인공호흡기 내장배터리는 짧으면 1시간인데, 정부 집계로 최근 3년 아파트 정전 382건 중 55건이 12시간을 넘겼습니다.

**AI(Claude)가 하는 일**
1. **라벨 판독(Sonnet):** 기기 라벨 사진의 글자를 옮겨 적습니다. 코드가 사양 DB와 정확히 맞을 때만 기종 후보로 삼습니다. 그때도 담당자가 「기종 확인」을 하기 전까지는 이웃 기종 중 가장 짧은 값으로 보수적으로 계산합니다.
2. **보호자 알림 글(Sonnet):** 담당자가 결정한 내용을 보호자용 쉬운 글로 씁니다. 두 검사를 모두 통과해야 후보가 되고, 아니면 코드가 만든 고정 문안을 씁니다.
   - 1차: 규칙 검사
   - 2차: 다른 AI(Claude Opus)가 글만 읽고 뽑은 주장을 코드가 결정 기록과 대조

계산·순서·배정은 AI가 아닌 규칙 코드가 하고, 결정은 사람이 합니다.

**검증은 이렇게 했습니다.**
- **사전등록과 봉인.** 예측·판정 기준·코드 해시를 봉인 실행 전에 커밋했습니다. S3는 sha256 매니페스트, S4~S9는 OpenTimestamps 비트코인 증명입니다.
  - 판정한 사전등록 59건(미검정·판정 불가 2건, 구조 확인 1건 제외)은 두 갈래로 나뉩니다.
    - 실행 전 예측 22건: 18건 맞힘
    - 개발 시드 예비 실행·사전 분석 뒤 정한 '확인' 37건: 35건 맞힘
  - S8(레드팀이 같은 효과를 먼저 본 뒤 씀)과 S9(개발셋을 보고 정한 문턱)는 전부 '확인' 쪽입니다.
  - **한계:** 모든 봉인에서 비트코인 블록 시각이 봉인 실행 시작보다 늦습니다. 순서의 근거는 git 커밋 시각과 OTS 캘린더 접수뿐입니다(README, `seal/CHANGELOG.md` '봉인 시각의 한계').
- **틀린 예측과 약점도 숫자로 공개합니다.**
  - 배터리 하한이 모의 실제보다 길게 나온 경우 14.9%(모의, 사전등록 밖 사후 집계)
  - 봉인 때 나간 알림 글 60건 중 21건은 봉인 뒤 결함 판정('적어도' 표현만 있는 8건은 기준 변경이라 제외, 합치면 29건)
- **적대적 검수(레드팀) 18라운드.** 마지막 라운드에서 치명·중대 0건으로 끝났습니다. 그 뒤에 반영한 경미 수정은 별도로 검수하지 않았습니다.

> **이 작업의 가장 중요한 원칙:** 화면은 얼마든지 좋아져도 됩니다. 다만 **숫자·공개된 한계·AI 표시·사람 승인 구조는 약해지면 안 됩니다.** 심사에서 "과장하지 않고 한계까지 공개한다"가 이 작품의 신뢰 근거입니다. 이 요약을 영상·홍보 문구로 옮길 때도 단서·한계 문장을 함께 옮겨 주세요.

### 3.3 브랜치와 배포

- fork에서 `design/…` 브랜치로 작업하고 PR로 올립니다.
- **금지:** `master`에 직접 push, 강제 push, 태그 삭제·이동(`git push --force`, `git push --delete`, `git tag -d`). 봉인 태그 S3~S9가 깨집니다(7장).

### 4.1 목표와 범위

- **목표:** 심사위원·투표자가 첫 10초 안에 "배터리 하한과 복구 시간을 비교해, 먼저 꺼질 집을 담당자가 먼저 챙기게 하는 도구"라고 이해하고, 믿을 만한 공공 서비스로 느끼게 합니다.
- **허용:** 색·타이포·간격·레이아웃·반응형, 화면 안 정보 배치와 흐름, 컴포넌트 분리·재구성, 전역 내비게이션 추가, 표·차트의 시각 표현 개선, 문구의 표현 다듬기(4.2절 범위 안에서).
- **대상 파일:**
  - `app/src/app/**`의 페이지·레이아웃(`page.tsx`, `layout.tsx`)
  - `app/src/components/**`
  - `app/src/app/globals.css`(디자인 토큰은 여기의 `@theme`)
  - `app/public/`(단, `samples/` 제외)
- **범위 밖(수정 금지):**
  - `app/src/app/api/**`(서버: 동의 검사·접근 코드·예산)
  - `app/src/lib/**`(계산 엔진·배정 규칙·AI 검사·고정 문안)

5. 커밋·공개 전에 `git status --porcelain --untracked-files=all submission/` 출력이 비어 있는지 확인합니다. Word·PDF 안의 코드는 `git grep`으로 찾을 수 없으므로, 파일이 추적 폴더에 생기지 않았는지를 이 명령으로 봅니다.
